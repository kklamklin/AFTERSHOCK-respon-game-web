## 1. ภาพรวม

### 1.1 คำอธิบาย

ผู้เล่นเป็นผู้บัญชาการศูนย์กู้ภัย ส่งเจ้าหน้าที่ 4 เผ่าเข้าช่วยผู้รอดชีวิต 1,200 คน ที่กระจายอยู่ใน 48 โซนทั่วเมืองที่เกิดแผ่นดินไหว ภายใต้ AP ที่จำกัดและเวลา 72 ชั่วโมงที่กำลังหมดลง

### 1.2 เงื่อนไขของโปรเจกต์

| หัวข้อ | รายละเอียด |
|---|---|
| กำหนดส่ง | ภายใน 1 สัปดาห์ |
| เกณฑ์ที่ครูเน้น | ความคิดสร้างสรรค์ + การนำเสนอหน้าชั้น |
| วิชา | สังคมศึกษา (เรื่องแผ่นดินไหว) |
| เป้าหมาย | สร้างสรรค์ แต่ประยุกต์เนื้อหาได้ |

### 1.3 หลักการที่ยึด

- **ความรู้อยู่ในกติกา** — มีบอกว่าต้องทำอะไร แต่ไม่สอนละเอียด
- **ไม่มีแพ้ชนะ มีแต่คะแนน** — จบเกมแสดงคะแนนรวม
- **แนวเกม** — Real-time with Pause (แบบ Plague Inc)

### 1.4 ตัวเลขหลักสรุป

```
เวลา              144 ลูป = 72 ชั่วโมงในเกม
ผู้รอดชีวิต        1,200 คน
โซน               48 โซน (เทา 27 / เหลือง 13 / แดง 8)
เจ้าหน้าที่         4 คน (Field 2 / Support 2)
สกิล              6 สกิล
AP รวมทั้งเกม      ~480 AP
AP ที่ต้องใช้จริง   ~670 AP (ถ้าจะเคลียร์ครบทุกโซน)
→ ทำได้จริง        ประมาณ 65-70% ของเมือง
```

## 4. ระบบผู้รอดชีวิต

### 4.1 การกระจาย

**รวมทั้งเมือง 1,200 คน** กระจายแบบสุ่มตามช่วงที่กำหนด

| ระดับ | โซน | คน/โซน (สุ่ม) | รวมประมาณ | สัดส่วน |
|---|---|---|---|---|
| 🔘 เทา | 27 | **8–11** | ~250 | 21% |
| 🟡 เหลือง | 13 | **26–36** | ~400 | 33% |
| 🔴 แดง | 8 | **60–80** | ~550 | 46% |
| | **48** | | **1,200** | 100% |

### 4.2 เหตุผลที่ให้คนกระจุกในโซนอันตราย

**เชิงเกม:** ถ้ากระจายเท่ากันทุกโซน ผู้เล่นจะฟาร์มโซนเทาอย่างเดียวเพราะคุ้มที่สุด (0.59 คน/AP เทียบกับโซนแดง 0.05 คน/AP) โซนแดงจะไม่ถูกแตะเลย

**เชิงเนื้อหา:** โซนแดงคืออาคารถล่ม คนติดอยู่ข้างในเยอะ ส่วนโซนเทาคือบ้านเรือนเสียหายเล็กน้อย คนออกมาเองได้เกือบหมดแล้ว

### 4.3 การสุ่มตอนเริ่มเกม

- สุ่มในช่วงที่กำหนดของแต่ละระดับ
- **ปรับตัวสุดท้ายให้ยอดรวมได้ 1,200 พอดี**
- ผลคือแต่ละโซนมีคนไม่เท่ากัน → ผู้เล่นต้องเลือกว่าจะบุกโซนไหนก่อน

### 4.4 ตัวแปรที่แต่ละโซนเก็บ

| ตัวแปร | ความหมาย |
|---|---|
| `trapped` | ผู้รอดที่ยังติดอยู่ (ยังช่วยได้) |
| `rescued` | ช่วยออกมาได้แล้ว → +1 คะแนน/คน |
| `casualty` | เสียชีวิตแล้ว → −1 คะแนน/คน |
| `cleared` | โซนถูกเคลียร์แล้วหรือยัง (true/false) |

**`trapped` ลดลงได้ 2 ทางเท่านั้น:** ถูกช่วย หรือ เสียชีวิต

## 5. ระบบการตาย

### 5.1 หลักการ

**การตายแบบเชิงเส้น** — แต่ละโซนมี "อายุ" ต่างกันตามระดับ ถ้าไม่มีใครไปช่วยเลย คนในโซนจะตายหมดพอดีเมื่อถึงลูปที่กำหนด

| ระดับ | ตายหมดที่ลูป | = ชั่วโมง | สูตรตายต่อลูป |
|---|---|---|---|
| 🔴 แดง | ลูป 48 | **24 ชม.** | `คนเริ่มต้น ÷ 48` |
| 🟡 เหลือง | ลูป 96 | **48 ชม.** | `คนเริ่มต้น ÷ 96` |
| 🔘 เทา | ลูป 144 | **72 ชม.** | `คนเริ่มต้น ÷ 144` |

### 5.2 ตัวอย่าง

| โซน | คนเริ่มต้น | ตาย/ลูป | ตาย/ชั่วโมง |
|---|---|---|---|
| แดง | 70 คน | 1.46 คน | ~2.9 คน |
| เหลือง | 30 คน | 0.31 คน | ~0.6 คน |
| เทา | 10 คน | 0.07 คน | ~0.14 คน |

### 5.3 ผลลัพธ์รวม

- **ถ้าไม่ช่วยใครเลย → 1,200 คนตายหมดพอดีตอนจบเกม** ✓
- 8 โซนแดง = สูญเสียประมาณ **23 คนทุกชั่วโมง**
- ถ้าไม่แตะโซนแดงเลย = เสีย 550 คน = **−1,100 คะแนน**

### 5.4 ข้อดีเชิงออกแบบ

โซนแดงหมดอายุตั้งแต่วันแรก (24 ชม.) / เหลืองวันที่สอง (48 ชม.) / เทาวันที่สาม (72 ชม.)

→ **ผู้เล่นถูกบังคับให้จัดลำดับความสำคัญด้วยตัวเอง โดยเกมไม่ต้องบอก**
→ ตรงกับหลัก 72 ชั่วโมงทองในงานกู้ภัยจริงพอดี

### 5.5 การจัดการทศนิยม

- เก็บค่าเป็น **ทศนิยม** ในระบบ
- แสดงบนจอเป็น **จำนวนเต็ม (ปัดลง)**
- ป้องกันปัญหาเศษสะสม

## 6. ระบบ Action Point

### 6.1 แนวคิด

AP = **กำลังเสริมและทรัพยากรที่ทยอยมาถึง** ยิ่งสถานการณ์หนัก ยิ่งมีความช่วยเหลือหลั่งไหลเข้ามา

### 6.2 รายรับ (จ่ายทุก 1 ชั่วโมง = ทุก 2 ลูป)

```
AP ต่อชั่วโมง = 5 + โบนัส
```

| ผู้รอดที่หายไปแล้ว (ตาย+ช่วยแล้ว) | โบนัส | AP/ชม. |
|---|---|---|
| 0–20% | +0 | **5** |
| 20–40% | +1 | **6** |
| 40–60% | +2 | **7** |
| 60–80% | +3 | **8** |
| 80–100% | +4 | **9** |

**AP รวมทั้งเกมประมาณ 480 AP**

### 6.3 กฎ

- **AP สะสมได้ ไม่มีเพดาน** — กั๊กไว้บุกโซนแดงได้
- AP ไม่พอ → ปุ่มจางลงและกดไม่ได้ พร้อมแสดงราคาที่ต้องใช้

### 6.4 ความย้อนแย้งที่ตั้งใจออกแบบ

> **ตอนที่มี AP มากที่สุด คือตอนที่แทบไม่เหลือใครให้ช่วยแล้ว**

ชั่วโมงแรก AP น้อย (5/ชม.) แต่คนรอดครบ 1,200
ชั่วโมงท้าย AP มาก (9/ชม.) แต่คนเหลือน้อยมาก

## 9. สูตรอัตราสำเร็จ

### 9.1 สูตรหลัก

```
อัตราสำเร็จ = %จนท. + %บัฟรวม − %ความเสี่ยงพื้นที่

if (อัตราสำเร็จ >= 100) → อัตราสำเร็จ = 99
```

### 9.2 ตัวประกอบทั้งหมด

## 10. ระบบผลลัพธ์การช่วย

### 10.1 การทอย

```
roll = สุ่ม 1–100
margin = อัตราสำเร็จ − roll
```

### 10.2 ตารางผลลัพธ์

| margin | ผลลัพธ์ | ช่วยได้ | สีโซน |
|---|---|---|---|
| **≥ 40** | 🟢 **สำเร็จสูงสุด** | **100%** ของที่ยังรอด | **เขียว — เคลียร์** |
| **15–39** | 🟢 **สำเร็จ** | **50–99%** (สุ่ม) | สีเดิม |
| **0–14** | 🟡 **สำเร็จต่ำ** | **1–49%** (สุ่ม) | สีเดิม |
| **< 0** | 🔴 **ไม่สำเร็จ** | **0%** | สีเดิม |

### 10.3 กฎสำคัญ

- **เฉพาะ "สำเร็จสูงสุด" เท่านั้นที่ทำให้โซนเป็นสีเขียว**
- สำเร็จ / สำเร็จต่ำ → โซนยังเป็นสีเดิม คนที่เหลือยังตายต่อไป **ต้องส่ง จนท. มาช่วยอีกรอบ**
- ไม่สำเร็จ → ไม่ได้อะไรเลย และเสีย AP ไปแล้ว

### 10.4 ผลข้างเคียงเชิงออกแบบ

**ยิ่งอัตราสำเร็จสูง ยิ่งมีโอกาสได้ "สำเร็จสูงสุด" มาก** → บัฟจึงคุ้มสองต่อ (ทั้งเพิ่มโอกาสสำเร็จ และเพิ่มโอกาสเคลียร์จบในครั้งเดียว)

| อัตราสำเร็จ | โอกาสสำเร็จสูงสุด | โอกาสไม่สำเร็จ |
|---|---|---|
| 35% | 0% | 65% |
| 50% | 10% | 50% |
| 65% | 25% | 35% |
| 80% | 40% | 20% |
| 90% | 50% | 10% |
| 99% | 59% | 1% |

## 11. ระบบอันตราย

### 11.1 หลักการ

**ทอยอันตรายก่อนทอยผลลัพธ์** — ถ้าทอยติด การช่วยกลายเป็น "ไม่สำเร็จ" ทันที ไม่ต้องทอยผลลัพธ์

### 11.2 สูตร

```
โอกาสอันตราย = ค่าพื้นฐานโซน × (1 + ชั่วโมงปัจจุบัน ÷ 72)

เพดานสูงสุด = 50%
มี Alert → 0% เสมอ
```

### 11.3 ค่าพื้นฐานตามโซน

| โซน | ค่าพื้นฐาน |
|---|---|
| 🔘 เทา | **5%** |
| 🟡 เหลือง | **15%** |
| 🔴 แดง | **30%** |

### 11.4 ตารางโอกาสอันตรายตามเวลา

| โซน | ชม. 0 | ชม. 18 | ชม. 36 | ชม. 54 | ชม. 72 |
|---|---|---|---|---|---|
| 🔘 เทา | 5.0% | 6.3% | 7.5% | 8.8% | 10.0% |
| 🟡 เหลือง | 15.0% | 18.8% | 22.5% | 26.3% | 30.0% |
| 🔴 แดง | 30.0% | 37.5% | 45.0% | **50%** (ตัน) | **50%** (ตัน) |

> โซนแดงชนเพดาน 50% ตั้งแต่ชั่วโมงที่ 48

### 11.5 สองขั้นของการบาดเจ็บ

```
ปกติ ──ทอยติด──> 🩹 INJURED ──ทอยติดอีก──> 💀 LOST CONSCIOUSNESS
                      │
                      └──รอ 3 ชั่วโมง──> กลับสู่ปกติ
```

| สถานะ | ผล | ระยะเวลา |
|---|---|---|
| 🩹 **Injured** | อัตราสำเร็จ **−20** · ยังทำงานได้ | ฟื้นเองใน **3 ชั่วโมง** |
| 💀 **Lost Consciousness** | **ทำอะไรไม่ได้เลย** | คูลดาวน์ **4 ชั่วโมง** |

### 11.6 การป้องกัน

- **Alert (35 AP)** → ไม่ทอยอันตรายเลยในโซนนั้น 3 ชั่วโมง
- ใช้กับ จนท. ที่ Injured อยู่ได้ = กันไม่ให้กลายเป็น Lost Consciousness

### 11.7 หมายเหตุ

- **ไม่มีการเสียชีวิตถาวรของ จนท.** — ยกเลิกระบบ "สูญเสีย" แล้ว ใช้ Lost Consciousness แทน
- **Support (เอลฟ์/ภูต) ไม่มีความเสี่ยงเลย** เพราะอยู่ศูนย์บัญชาการ
- **Crowd Control มีความเสี่ยง** เพราะมนุษย์ต้องลงพื้นที่จริง

## 12. ระบบคะแนน

### 12.1 สูตร

| รายการ | คะแนน |
|---|---|
| ช่วยผู้รอดได้ (Rescue) | **+1 ต่อคน** |
| ผู้รอดเสียชีวิต (Casualty) | **−1 ต่อคน** |

**ไม่มีแต้มลบจากการเสีย จนท.** เพราะ จนท. ไม่ตายถาวรแล้ว

### 12.2 ช่วงคะแนนที่เป็นไปได้

```
คะแนน = rescued − casualty
casualty = 1,200 − rescued

→ คะแนน = (rescued × 2) − 1,200
```

| ช่วยได้ | คะแนน |
|---|---|
| 0 คน | **−1,200** |
| 300 คน | −600 |
| 600 คน | **0** |
| 800 คน | +400 |
| 1,000 คน | +800 |
| 1,200 คน | **+1,200** |

### 12.3 หน้า Result

```
ผลปฏิบัติการ

ผู้รอดชีวิตทั้งหมด      1,200 คน
├─ ช่วยเหลือสำเร็จ        712 คน    +712
└─ เสียชีวิต             488 คน    −488
─────────────────────────────────────
คะแนนรวม                            224

อัตราการช่วยเหลือ  59.3%
โซนที่เคลียร์ได้    31 / 48
```

## 13. เงื่อนไขจบเกม

### 13.1 จบปกติ

| เงื่อนไข | ผล |
|---|---|
| ครบ 144 ลูป (72 ชั่วโมง) | → หน้า Result |
| ผู้รอดหมดทุกโซน (`trapped` รวม = 0) | → หน้า Result ทันที |

### 13.2 จบก่อนกำหนด — CRITICAL

```
จนท. ภาคสนามทั้ง 2 คน (มนุษย์ + สาวแมว) Lost Consciousness พร้อมกัน
        ↓
⚠ CRITICAL — นับถอยหลัง 3 ชั่วโมง
        ↓
┌─ คนใดคนหนึ่งฟื้นทัน → กลับสู่ปกติ เล่นต่อ
└─ ครบ 3 ชั่วโมงยังล้มทั้งคู่ → จบเกม สรุปผล
```

**เหตุผล:** Lost Consciousness คูลดาวน์ 4 ชม. ดังนั้นถ้าล้มไม่พร้อมกันเป๊ะ มีโอกาสฟื้นทัน
→ ผู้เล่นที่บริหารดีจะรอด ผู้เล่นที่ส่งลุยทั้งคู่พร้อมกันจะจบ

## 18. สิ่งที่ยังไม่เคาะ

### 18.1 Flow ผู้เล่น (กำลังร่างในอีกแชท)

คำถามที่ flow ต้องตอบ:

1. เลือกหน่วยก่อนแล้วค่อยเลือกโซน หรือกลับกัน?
2. **กด Deploy แล้วเห็นอัตราสำเร็จก่อนยืนยันไหม?**
   → ควรเห็น เพราะเป็นหัวใจของหลัก "ผู้เล่นต้องเมคชัวก่อน"
3. บัฟต้องลงก่อน Deploy หรือลงพร้อมกันได้?
4. ผลลัพธ์แสดงยังไง — เด้งกลางจอ หรือขึ้นบนโซน?
5. ตอน จนท. Injured เกมเตือนยังไงให้ผู้เล่นไม่พลาด?

| ไม่มีใครเข้าโซนแดง | เพิ่มคนในโซนแดง หรือลด AP |
| ไม่มีใครใช้ Alert | เพิ่มโอกาสอันตราย หรือลดราคา |
| ชนะง่ายเกินไป | ลด AP ต่อชั่วโมง หรือเพิ่มอัตราตาย |
| จนท. ล้มบ่อยจนหงุดหงิด | ลดโอกาสอันตราย หรือลดเวลาฟื้น |
| ทุกคนเล่นเหมือนกันหมด | ถ่างตัวเลขระหว่างทางเลือกให้ต่างกันมากขึ้น |

**เป้าหมาย:** คนเล่นครั้งแรกควรได้อัตราช่วยเหลือ **50–65%**
