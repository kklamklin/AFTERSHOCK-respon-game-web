## ก่อนอื่น: อ่าน `CLAUDE.md` ให้จบก่อนแตะโค้ด

กฎทั้งหมดของโปรเจกต์อยู่ที่นั่น ไม่ใช่ที่นี่ ย้ำเฉพาะข้อที่พลาดกันบ่อยที่สุด:

| กฎ | ทำไม |
|---|---|
| **vanilla JS ล้วน** ไม่มี framework ไม่มี build step ไม่มี dependency | ปลายทางคือ GitHub Pages เปิดตรง ๆ |
| **ตัวเลขบาลานซ์ทุกตัวอยู่ `src/config.js` เท่านั้น** | เจ้าของต้องปรับหลังลองเล่น ห้าม hardcode กระจาย |
| **`src/systems/` ห้ามแตะ DOM · `src/ui/` ห้ามคำนวณกฎเกม** | เส้นแบ่งนี้ทำให้เทสแบบไม่มีหน้าจอได้ |
| **คอมเมนต์เป็นภาษาไทย** อ้างหัวข้อสเปก | เจ้าของอ่านโค้ดเองไม่ได้ ต้องอ่านคอมเมนต์แทน |
| **ห้ามใช้หน่วย `vh`/`vw` ในของที่อยู่ในเวที** | เวทีล็อก 1320×600 แล้ว scale เอา ใส่ vh/vw สัดส่วนหลุดทันที |
| **ของที่ทำงานทุกเฟรม ห้ามแตะ `left/top/width/background-position`** ใช้ `transform`/`opacity` | รอบแก้แล็คบน iOS แลกมาด้วยการวัดจริง อย่าทำพัง |
| **ทดสอบในเบราว์เซอร์จริงก่อนบอกว่าเสร็จ** | ห้ามเดาว่าโค้ดทำงานถูก |
| **ห้ามเปิด PR เว้นแต่ถูกสั่ง** | เจ้าของสั่งเอง |

## กติกาการใช้สมุดเล่มนี้

1. **ก่อนเริ่มงาน** — `git fetch origin` แล้วอ่านไฟล์นี้ ดูว่าอีกฝั่งกำลังจับไฟล์ไหนอยู่
2. **ก่อนจะแตะไฟล์ที่ใช้ร่วมกัน** — จองในตาราง "ไฟล์ที่ใช้ร่วมกัน" ด้านล่างก่อน push
3. **ทุกครั้งที่ push** — เขียนลงท้าย "บันทึกงาน" ว่าทำอะไรไปแล้ว
4. **มีคำถามถึงอีกฝั่ง** — เขียนใน "คำถามค้าง" แล้ว push แล้ว**บอกเจ้าของให้ไปสะกิดอีกแชต**
   (สองแชตไม่เห็นกันเอง ไม่มีใครมาเตือน ต้องให้เจ้าของเป็นคนบอก)
5. **ห้ามลบของที่อีกฝั่งเขียน** — ขีดฆ่าหรือทำเครื่องหมาย ✅ แทน

## นัดกันตอน merge (ยังไม่ถึงเวลา)

ตอน DLC เสร็จพร้อมขึ้นเว็บจริง ให้ทำตามนี้ **อย่าเพิ่งทำตอนนี้ รอเจ้าของสั่ง**

1. Building 21 เขียนใน "บันทึกงาน" ว่าพร้อม merge แล้ว + ลิสต์ไฟล์ร่วมที่แตะไปทั้งหมด
2. เจ้าของบอกแชต A
3. **แชต A เป็นคน merge** (เพราะ branch ตัวเองคือตัวที่ Pages เสิร์ฟ) แล้วรันเทสเดิมทั้งชุดซ้ำ
   — อย่างน้อย `layout.js` · `devices.js` · `intelfacts.mjs` · `keys.js` · `qte.js`
4. เทสผ่านครบค่อย push · ไม่ผ่านให้เขียนกลับมาในไฟล์นี้ว่าพังตรงไหน

**เกมหลักต้องเล่นได้เหมือนเดิม 100% หลัง merge** — DLC เพิ่มของใหม่ได้ แต่ห้ามทำของเดิมพัง
