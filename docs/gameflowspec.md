## 1. 🔴 กฎใหม่ที่เปลี่ยนระบบเดิม

### 1.1 ย้ายจุดคำนวณ — สำคัญที่สุด

| | เดิม | **ใหม่** |
|---|---|---|
| คำนวณตอนไหน | ทันทีที่กด Deploy | **หลัง จนท. ปฏิบัติงานเสร็จ** |
| คำนวณอะไร | ผลสำเร็จ + สถานะบาดเจ็บ | เหมือนกัน แต่เลื่อนไปตอนจบงาน |
| คูลดาวน์คืออะไร | เวลาพักหลังทำงาน | **เวลาที่ จนท. กำลังทำงานอยู่ในโซน** |

**ความหมายใหม่ของคูลดาวน์:**

```
กด Deploy ──> จนท. เข้าไปทำงานในโซน ──> ครบเวลา ──> คำนวณผล
             (คูลดาวน์ = ช่วงนี้)          (2 ชม.)      (สำเร็จ/ไม่สำเร็จ)
                    ↑
        ระหว่างนี้คนในโซนยังตายอยู่เรื่อย ๆ
```

### 1.2 ผลกระทบที่ตามมา

| ผลกระทบ | รายละเอียด |
|---|---|
| ✅ **บัฟทีหลังมีผลจริง** | ตอบข้อ C3 ได้สมเหตุสมผล เพราะยังไม่ได้คำนวณ |
| ⚠️ **คนตายระหว่างรอ** | ส่งแมวเข้าโซนแดง (2 ชม.) = คนตายไปอีก ~6 คนก่อนรู้ผล |
| ⚠️ **เดิมพันสูงขึ้น** | ไม่สำเร็จ = เสียทั้ง AP + เสียเวลา 2 ชม. + คนตายไปแล้ว |
| ✅ **มีช่วงลุ้น** | เกมมีจังหวะตื่นเต้นระหว่างรอผล |

### 1.3 ตัวอย่างเวลาจริง

```
ชม. 10:00  ลากแมวลงโซนแดง (คน 70, ตาย 2.9/ชม.)  → หัก 30 AP
ชม. 10:00  โซนแสดงไอคอนแมว + นับถอยหลัง 2:00
ชม. 11:00  ลาก Scan Area ลงโซนเดียวกัน → หัก 10 AP → บัฟติด
ชม. 12:00  ครบ 2 ชม. → คำนวณ!
           คนในโซนเหลือ 70 − 5.8 = 64 คน
           อัตราสำเร็จ = 90 + 15 − 55 = 50%
           ทอย → สำเร็จ → โซนเขียว
```

## 2. ระบบผลลัพธ์ใหม่

### 2.1 เหลือแค่ 2 สถานะ (จากเดิม 4)

| ผลลัพธ์ | โซน | ผู้รอด | สถานะ จนท. |
|---|---|---|---|
| 🟢 **สำเร็จ** | **เขียว — เคลียร์แล้ว** | สุ่มตาม % อัตราช่วยชีวิต | ปกติ |
| 🔴 **ไม่สำเร็จ** | **สีเดิม — ยังไม่เคลียร์** | ไม่ได้ใครเลย | **อาจได้สถานะบาดเจ็บ** |

### 2.2 ลำดับการทอย (สรุปจาก Q2)

```
จนท. ทำงานครบชั่วโมง
        ↓
   ทอยผลสำเร็จ  (roll 1–100 เทียบอัตราสำเร็จ)
        ↓
   ┌────┴────┐
   ↓         ↓
🟢 สำเร็จ   🔴 ไม่สำเร็จ
   │         │
   │         ↓
   │    ทอยอันตราย (roll เทียบ %อันตรายพื้นที่)
   │         ├─ ไม่ติด → รอดไป
   │         └─ ติด   → บาดเจ็บ
   ↓
จบเลย — ไม่ทอยอันตราย
```

**กฎสำคัญ: สำเร็จ = ปลอดภัยเสมอ** ไม่ต้องทอยอันตรายเลย

### 2.3 จำนวนผู้รอดที่ช่วยได้ (เมื่อสำเร็จ)

**คนที่ช่วยไม่ได้ = เสียชีวิตทันที** และโซนปิดเป็นเขียว

```
ช่วยได้  = trapped × %ช่วยชีวิต
เสียชีวิต = trapped × (1 − %ช่วยชีวิต)
โซน → เขียว (เคลียร์)
```

**ตัวอย่าง:** โซนมี 70 คน → สำเร็จที่ 70% → **รอด 49 คน · ตาย 21 คน** → โซนเขียว

⚠️ **ยังไม่เคาะ: %ช่วยชีวิต มาจากไหน** — ดูหัวข้อ 13 คำถาม Q1b

### 2.4 ที่ยกเลิกไปแล้ว

- ~~สำเร็จสูงสุด / สำเร็จ / สำเร็จต่ำ~~ (ระบบ margin 4 ระดับ)
- ~~ระบบ "สูญเสีย" (จนท. ตายถาวร)~~
- ~~แต้มลบจากการเสีย จนท.~~

## 3. หมวด A — การเลือกและสั่งการ

### A1 — ลำดับการกด

**เลือกหน่วยก่อน → ลากไอคอนไปวางบนโซน**

- ระบบเป็น **Drag & Drop** ไม่ใช่การกดเลือกสองครั้ง
- **ขณะลาก เกมหยุดเวลาอัตโนมัติ**
- ปล่อยไอคอน = ยืนยันทันที ไม่มีขั้นตอนกดยืนยันซ้ำ

### A2 — โซนที่ลงไม่ได้

- แสดง **กากบาท ✕** บนโซนนั้น
- **ลากไปวางไม่ได้** (ระบบปฏิเสธการ drop)

**ตัวอย่าง:** เลือกมนุษย์ → โซนแดงทั้ง 8 ขึ้นกากบาท

### A3 — การยกเลิก

- **ปล่อยไอคอนนอกโซนที่ลงได้ = ยกเลิกอัตโนมัติ**
- ไม่มีปุ่มยกเลิกแยก
- ไอคอนเด้งกลับที่เดิม เกมเดินเวลาต่อ

### A4 — หน่วยที่ติดคูลดาวน์

- **เลือกไม่ได้เลย** (ลากไม่ขึ้น)
- **แสดงตัวเลขคูลดาวน์บนไอคอนหน้า จนท.**

## 4. หมวด B — อัตราสำเร็จและการยืนยัน

### B1 + B2 — เห็นอัตราตอนไหน

**เห็นตอนลากไอคอนผ่านโซนนั้น (hover ระหว่าง drag)**

```
┌─ ปกติ ────────────────────────┐
│  แผงล่าง = ข้อมูลพื้นที่       │
└───────────────────────────────┘
              ↓ ลากไอคอนผ่านโซน
┌─ ระหว่างลาก ──────────────────┐
│  แผงล่าง = ข้อมูลอัตรา จนท.   │  ← แทนที่ชั่วคราว
└───────────────────────────────┘
```

### B3 — แสดงแยกส่วน

```
🐱 สาวแมว → โซนแดง C-03

  อัตราพื้นฐาน          +90
  Scan Area             +15
  ความเสี่ยงพื้นที่      −55
  ─────────────────────────
  อัตราสำเร็จ            50%
```

### B4 — แสดงความเสี่ยงด้วย

```
  ความเสี่ยงบาดเจ็บ      37%
```

### B5 — การยืนยัน

**ไม่มีขั้นตอนยืนยัน** — ลากแล้วปล่อยตรงโซนไหนก็ลงโซนนั้นทันที
ปล่อยนอกโซนที่ลงได้ = ยกเลิก

### B6 — แผงล่างแสดงอะไรบ้าง

| รายการ | ตัวอย่าง |
|---|---|
| ค่า AP | `30 AP` |
| อัตราสำเร็จ (แยกส่วน) | `90 +15 −55 = 50%` |
| ความเสี่ยงบาดเจ็บ | `37%` |

## 5. หมวด C — ระบบบัฟ

### C1 — วิธีลงบัฟ

**ลากไอคอนสกิลไปวาง เหมือนกับการส่ง จนท. ทุกประการ**
ไม่มีโหมดแยก ใช้กลไกเดียวกันหมด

### C2 — ลำดับการลงบัฟ

**ลงก่อนหรือหลัง Deploy ก็ได้**

### C3 — บัฟมีผลกับ จนท. ที่ลงไปแล้ว

**✅ มีผล** — เพราะการคำนวณเกิดขึ้นตอนจบงาน ไม่ใช่ตอน deploy

> นี่คือกลยุทธ์ใหม่ที่เกิดจากกฎใหม่:
> ส่ง จนท. ลงก่อน แล้วค่อยหา AP มาบัฟระหว่างที่เขากำลังทำงาน

### C4 — Scan Area หลายโซน

**ลากทีละโซน** — ลาก 3 โซน = ลาก 3 ครั้ง = 30 AP

### C5 — การแสดงบัฟบนแผนที่

**ไอคอนสกิลเล็ก ๆ วางบนโซนนั้น**

### C6 — ยกเลิกบัฟ

**❌ ยกเลิกไม่ได้ ไม่คืน AP** — ต้องตัดสินใจให้ดีก่อนลง

### C7 — Air Deploy (บัฟทั้งแมพ)

**ไอคอนตัวละครภูตเรืองแสง** ระหว่างที่บัฟยังมีผล
(ไม่แสดงไอคอนบนทุกโซน เพราะจะรก)

## 6. หมวด D — การแสดงผลลัพธ์

### D1 — รูปแบบ

**ลอยขึ้นเหนือโซนนั้น** ไม่เด้งกลางจอ

### D2 — ไม่หยุดเวลา

โซนเปลี่ยนเป็นเขียวเองเมื่อสำเร็จ → ไม่ต้องหยุดเกม

### D3 — ไม่ต้องกดปิด

หายเอง ไม่มีปุ่ม "ไปต่อ"

### D4 — แสดงอะไร

**บนโซน:** คะแนนลอยขึ้นสักพักแล้วหายไป
```
        +64
    ╔═════════╗
    ║  เขียว  ║
    ╚═════════╝
```

**แถบ Detail Feed ด้านขวาจอ:** รายละเอียดเต็ม
```
┌─ FEED ──────────────────┐
│ 12:00 🟢 C-03 สำเร็จ     │
│       ช่วยได้ 64 คน      │
│                         │
│ 11:30 🔴 B-07 ไม่สำเร็จ  │
│       👤 บาดเจ็บ         │
└─────────────────────────┘
```

### D5 — ไม่ซ้อนทับ

ผลลัพธ์แต่ละอันลอยขึ้นบนโซนของตัวเอง ไม่ทับกัน

### D6 — ไม่มี log ย้อนหลัง

มีแค่ Detail Feed ที่ไหลผ่านไปเรื่อย ๆ

## 7. หมวด E — สถานะเจ้าหน้าที่

## 12. Flow สมบูรณ์

### 12.1 Flow หน้าจอ

```
[หน้าเริ่มเกม]
   ├─ ชื่อเกม
   ├─ ปุ่มเริ่ม ──> [หน้าสอนกติกา] ──> [หน้าเกม]
   └─ ปุ่มสอนกติกา
                                          │
                                          ↓
                                   [หน้า Result]
                                    ├─ คะแนน
                                    ├─ ปุ่ม Home
                                    ├─ ปุ่มเล่นใหม่
                                    └─ ปุ่มแชร์
```

### 12.2 Flow การส่งเจ้าหน้าที่

```
1. ผู้เล่นแตะไอคอน จนท. ค้างไว้
        ↓
2. ⏸ เกมหยุดเวลาอัตโนมัติ
        ↓
3. โซนที่ลงไม่ได้ขึ้นกากบาท ✕
        ↓
4. ลากไอคอนไปเหนือโซน
        ↓
5. แผงล่างเปลี่ยนเป็นข้อมูลอัตรา:
   ├─ ค่า AP
   ├─ อัตราสำเร็จ (แยกส่วน)
   └─ ความเสี่ยงบาดเจ็บ
        ↓
6. ปล่อยไอคอน
   ├─ บนโซนที่ลงได้ → ไปข้อ 7
   └─ ที่อื่น → ยกเลิก กลับข้อ 1
        ↓
7. หัก AP · ไอคอน จนท. ไปอยู่บนโซน · เริ่มนับคูลดาวน์
        ↓
8. ▶ เกมเดินเวลาต่อ
        ↓
9. ระหว่างนี้:
   ├─ คนในโซนยังตายเรื่อย ๆ
   ├─ ผู้เล่นลงบัฟเพิ่มได้ (มีผลกับ จนท. ที่ลงไปแล้ว)
   └─ ไอคอน จนท. แสดงเวลาที่เหลือ
        ↓
10. ครบเวลา → 🎲 คำนวณผล
    ├─ ทอยอันตราย → บาดเจ็บไหม
    └─ ทอยผลสำเร็จ → สำเร็จ/ไม่สำเร็จ
        ↓
11. แสดงผล:
    ├─ 🟢 สำเร็จ → โซนเขียว + คะแนนลอยขึ้น + FEED
    └─ 🔴 ไม่สำเร็จ → โซนสีเดิม + FEED (+ ป๊อปอัพถ้าบาดเจ็บ)
        ↓
12. จนท. กลับมาพร้อมใช้งาน
```

### 12.3 Flow การลงบัฟ

```
เหมือนการส่ง จนท. ทุกประการ ต่างกันที่:
├─ ลากไอคอน "สกิล" แทนไอคอนตัวละคร
├─ ลงได้ทุกโซน (ยกเว้น Air Deploy ที่เป็นทั้งแมพ)

└─ แสดงเป็นไอคอนเล็กบนโซน
```

## 13. ✅ คำตอบทั้งหมด

### Q1 — คนที่ช่วยไม่ได้ตอนสำเร็จ

**ตอบ: นับเป็นเสียชีวิตทั้งหมด**

> สำเร็จที่ 70% หมายถึง **70% นั้นรอดหมด อีก 30% ตายหมด**

```
สำเร็จ → โซนเขียว
       → รอด  = trapped × %ช่วยชีวิต
       → ตาย  = trapped × (1 − %ช่วยชีวิต)
```

---

### Q2 — ลำดับการทอย

**ตอบ: ทอยสำเร็จก่อน → ถ้าไม่สำเร็จค่อยทอยอันตราย**

| ผล | ทอยอันตรายไหม |
|---|---|
| 🟢 สำเร็จ | **ไม่ทอย — จบเลย ปลอดภัย 100%** |
| 🔴 ไม่สำเร็จ | **ทอยตาม %อันตรายพื้นที่** ติด = บาดเจ็บ / ไม่ติด = รอด |

#### ⚠️ ผลกระทบต่อบาลานซ์ (สำคัญ)

โอกาสบาดเจ็บจริง = `(1 − อัตราสำเร็จ) × %อันตรายพื้นที่`

| สถานการณ์ | สำเร็จ | อันตราย | **บาดเจ็บจริง** |
|---|---|---|---|
| แมวเดี่ยว → แดง (ชม.0) | 35% | 30% | **19.5%** |
| แมว+Scan → แดง | 50% | 30% | **15.0%** |
| แมว+Scan+Crowd → แดง | 75% | 30% | **7.5%** |
| แมวชุดเต็ม → แดง | 90% | 30% | **3.0%** |
| แมวเดี่ยว → แดง (ชม.48+) | 35% | 50% | **32.5%** |
| มนุษย์ → เหลือง (ชม.0) | 45% | 15% | **8.2%** |
| มนุษย์+Scan → เหลือง | 60% | 15% | **6.0%** |
| แมว → เทา (ชม.0) | 80% | 5% | **1.0%** |

**ข้อดี:** บัฟช่วย 2 ต่อโดยอัตโนมัติ — เพิ่มโอกาสสำเร็จ และลดโอกาสบาดเจ็บไปพร้อมกัน สอนหลัก "เตรียมพร้อมก่อนลงพื้นที่" ได้ในตัว

**ข้อควรระวัง:** Alert (35 AP) ที่กันบาดเจ็บ 100% มีค่าน้อยลงมาก เพราะตอนนี้บาดเจ็บเกิดยากอยู่แล้ว — ต้องจับตาตอนทดสอบ

## 14. ⚠️ เหลือคำถามเดียว

### 🔴 Q1b — "%ช่วยชีวิต" มาจากไหน

ตอนนี้เรารู้แล้วว่าคนที่ช่วยไม่ได้จะตาย แต่ยังไม่รู้ว่า **ตัวเลข % นั้นคำนวณยังไง**

จากคำว่า *"ช่วยสำเร็จปานกลาง (70%)"* ดูเหมือนจะมีระดับของความสำเร็จ

| ทางเลือก | วิธีคำนวณ | ผล |
|---|---|---|
| **ก.** สุ่มช่วงคงที่ | สุ่ม 60–100% ทุกครั้ง | ง่ายสุด แต่บัฟไม่มีผลต่อจำนวนคนที่รอด |
| **ข.** ผูกกับอัตราสำเร็จ | %ช่วยชีวิต = อัตราสำเร็จ | บัฟคุ้ม 3 ต่อ · แต่โซนแดงจะช่วยได้น้อยมาก |
| **ค.** แบ่งเป็นระดับ | สูง 90–100% / กลาง 60–89% / ต่ำ 30–59% | ตรงกับคำว่า "ปานกลาง" ที่สุด · ต้องกำหนดว่าอะไรตัดสินระดับ |
| **ง.** สุ่มโดยอิงอัตราสำเร็จ | สุ่มระหว่าง (อัตราสำเร็จ) ถึง 100% | ประนีประนอม บัฟช่วยแต่ไม่โหด |

**ตัวอย่างความต่าง** — โซนแดง 70 คน สำเร็จที่อัตรา 50%

| ทางเลือก | ช่วยได้ | ตาย |
|---|---|---|
| ก. สุ่ม 60–100% | 42–70 คน | 0–28 คน |
| ข. = 50% | 35 คน | 35 คน |
| ง. สุ่ม 50–100% | 35–70 คน | 0–35 คน |

## ภาคผนวก: สรุปการเปลี่ยนแปลงจากเอกสารเดิม

| หัวข้อ | เดิม | ใหม่ |
|---|---|---|
| จุดคำนวณ | ตอน Deploy | **ตอนงานเสร็จ** |
| ความหมายคูลดาวน์ | เวลาพัก | **เวลาทำงาน** |
| ผลลัพธ์ | 4 ระดับ (margin) | **2 ระดับ (สำเร็จ/ไม่สำเร็จ)** |
| การเคลียร์โซน | เฉพาะ "สำเร็จสูงสุด" | **สำเร็จ = เคลียร์เลย** |
| จำนวนคนที่ช่วยได้ | ตาม margin | **สุ่มตาม %** |
| การสั่งงาน | กดเลือก 2 ครั้ง | **ลากวาง (Drag & Drop)** |
| การยืนยัน | มีแผงยืนยัน | **ไม่มี ปล่อยคือยืนยัน** |
| บัฟหลัง Deploy | ไม่มีผล | **มีผล** |
| เวลาที่เหลือของโซน | แสดง | **ไม่แสดง (ให้ลุ้น)** |
| Layout | จอตั้ง | **จอนอน (บังคับ)** |
